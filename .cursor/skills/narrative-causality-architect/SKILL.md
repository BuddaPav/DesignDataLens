# Narrative Causality Architect

## Назначение

Используй этот skill, когда нужно:
- выстроить причинно-следственную цепочку событий в сюжете;
- спроектировать последовательность сцен и квестовых узлов;
- сделать ветвление с понятными последствиями;
- проверить, что механика поддерживает narrative beat без soft-lock.

## Контракт работы

1. Определи инварианты мира:
   - какие факты уже установлены;
   - какие условия входа/выхода для узла обязательны;
   - какие ресурсы критичны (предмет, NPC, доступ к локации).
2. Построй граф причинности:
   - `cause -> event -> consequence`;
   - краткосрочные и отложенные последствия;
   - позитивные и негативные развилки.
3. Проверь совместимость с механикой:
   - сюжетный шаг должен быть выражен через типы/состояние игры;
   - без дублирующих источников правды для флагов;
   - без тупиков, где игрок не может продолжить.
4. Добавь fail-forward:
   - если критический путь срывается, предложи альтернативный способ прогресса;
   - не блокируй основной контур истории.

## Обязательный формат ответа

Выдавай результат в этой структуре:

### 1) Causal Chain
- `Причина: ...`
- `Событие: ...`
- `Непосредственное следствие: ...`
- `Долгосрочное следствие: ...`

### 2) Story Sequence
- `Scene 1: цель, входные условия, результат`
- `Scene 2: цель, входные условия, результат`
- `Scene 3+: ...`

### 3) Branches
- `Ветка A (успех): ...`
- `Ветка B (частичный успех / fail-forward): ...`
- `Ветка C (ошибка игрока, но без soft-lock): ...`

### 4) Mechanics Alignment Check
- `Какие флаги/состояния нужны в игре`
- `Какие предметы/NPC критичны`
- `Где риск soft-lock и как устранён`

## Правила качества

- Каждый сюжетный узел имеет явные условия входа и выхода.
- Каждое следствие имеет игровое проявление (репутация, доступ, ресурсы, состояние мира).
- Нет "магических" развилок без причины в предыдущих сценах.
- Важные последствия должны быть отслеживаемыми в игровом состоянии.
- При конфликте "красиво в сюжете" vs "ломает игру" приоритет у устойчивого геймплея.

## Чего избегать

- Ретконов без объяснённой причины.
- Ключевых предметов в единственном хрупком источнике без альтернативы.
- Ложного выбора (две опции, одинаковый результат) без явного нарративного смысла.
- Новых сущностей, которые дублируют уже существующие типы/флаги.

## Мини-чеклист перед финалом

- [ ] Причинно-следственная цепочка непрерывна.
- [ ] Переходы между сценами обоснованы.
- [ ] Есть хотя бы один fail-forward путь.
- [ ] Нет soft-lock сценариев.
- [ ] Последствия выражаются через игровое состояние.
