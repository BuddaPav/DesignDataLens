# Плагин **scaffold** — архитектурные шаблоны

## Назначение

При добавлении новой игровой системы **не писать с нуля**, а выбрать проверенный шаблон из `app/src/scaffolds/`, адаптировать под домен Chronos и расширять через `@/domain/**` и `@/types/game`.

## Доступные шаблоны

| Шаблон | Файл | Когда использовать |
|--------|------|-------------------|
| **Event Bus** | `EventBus.ts` | События между подсистемами без жёсткой связи |
| **Object Pool** | `ObjectPool.ts` | Частые аллокации однотипных объектов (снаряды, частицы) |
| **State Machine** | `StateMachine.ts` | Явные состояния UI/агента/боя |
| **ECS (лёгкий)** | `EcsLite.ts` | Сущности + компоненты без тяжёлого ECS-движка |
| **Behavior Tree (заготовка)** | `BehaviorTreeStub.ts` | ИИ / последовательность узлов «проверка→действие» |

Точка входа: `app/src/scaffolds/index.ts`.

## Best practices (целевая платформа: браузер + Electron)

- **Web:** избегать аллокаций в горячем цикле; пул для временных объектов; не создавать замыкания в `requestAnimationFrame` без нужды.
- **Three.js:** инстансинг / слияние геометрий вместо тысяч отдельных мешей; материалы переиспользовать.
- **Electron:** тяжёлое оставлять в worker или batch; не блокировать main-процесс.

Подробности по бюджетам: `docs/orchestrate/perf-budgets.json`, плагин [perf](./perf.md).

## Процесс для Orchestrate

1. Определить тип системы → выбрать шаблон из таблицы.
2. Скопировать/импортировать минимальный API в доменный модуль (не раздувать `scaffolds/` продакшен-логикой).
3. Добавить тесты контракта рядом с доменом (`*.test.ts`).
