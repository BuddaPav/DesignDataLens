# Плагин **prototype** — быстрая валидация идей

## Приоритет

1. **Работает ли механика?** (ввод, состояние, победа/поражение условия)
2. **Выглядит ли хорошо?** — только после (1)

## Визуал

- Серые боксы / placeholder-меши / цветовые CAP вместо финальных ассетов.
- Не тянуть из `public/` финальный арт без необходимости.

## TTL прототипа

- **Максимум 2 часа** на проверку одного концепта — таймер обязанности разработчика/ревьюера, не автоматический таймер в CI.
- Маркировка кода: комментарий в корне экспериментальной папки или в первом файле:
  - `// [PROTOTYPE] expires: YYYY-MM-DD or session — owner: <who>`
- По истечении TTL: **решение человека** — merge в основной дизайн, перенос в домен, или удаление.

## Удаление не прошедшего валидацию

**Политика безопасности:** Orchestrate и агент **не удаляют** файлы автономно.

Разрешено:

- Предложить PR/дифф на удаление и список файлов.
- Чеклист в комментарии к задаче: «прототип X не прошёл — удалить каталог Y».

Автоматическое `rm`/`git clean` по TTL **запрещено** без явной команды пользователя.

## Связь с gate

Прототипный код не должен ломать `npm run orchestrate:gate`. Если ломает — либо изолируй за флагом `import.meta.env.DEV`, либо вынеси в отдельную ветку до стабилизации.
