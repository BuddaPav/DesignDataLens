# Плагин **asset-pipeline** — управление контентом

## Цели

1. **Оптимизация** моделей/текстур под целевые спеки (разрешение, формат, mipmaps).
2. **Зависимости** ассет ↔ код (скрипт аниматора → какие компоненты его дергают).
3. **Версионирование** и **fallback** при битых ссылках.

## Реализация в репозитории

- Кураторский список внешних стоков и лицензий: `docs/orchestrate/GRAPHICS_SOURCES.md`.
- Генерация атласов и синхронизация версий уже частично в `npm run prebuild` / скриптах `scripts/generate-*.mjs`.
- После атласа выполняется `scripts/vendor-kenney-icons.mjs` (HUD иконки NPC/UI из Kenney CC0); при недоступности сети скрипт пропускает загрузку, если целевые PNG уже лежат в `public/`.
- Инвентаризация публичных файлов (напоминание проверить ссылки):

```bash
cd app && npm run orchestrate:assets
```

Скрипт выводит список под `public/` для ручной сверки с импортами.

## Правила для Orchestrate

- При смене пути ассета — обновить все импорты и i18n при необходимости.
- При добавлении тяжёлого контента — сверить с `docs/orchestrate/perf-budgets.json`.
- Битая ссылка: предпочтительно **явный fallback** (placeholder-текстура / mesh) + запись в ADR или issue, а не молчаливый `catch`.

## Отслеживание «аниматор ↔ скрипты»

Пока без автоматического графа: при изменении анимационного или Three-слоя grep по имени клипа / компонента и ручной чеклист в PR.

Будущее улучшение: скрипт поиска строк по префиксу `animation:` в кодовой базе (отдельная задача).
